## 2. Acceptance Criteria

### AC-01 — การค้นหาและตรวจสอบสถานะว่างของพื้นที่และอุปกรณ์

- **Given** นักศึกษาเข้าสู่หน้าค้นหาพื้นที่กลุ่มและอุปกรณ์การเรียน
- **When** ระบุวันที่ ช่วงเวลา จำนวนผู้ใช้งาน หรือประเภทอุปกรณ์ที่ต้องการ
- **Then** ระบบแสดงรายการห้อง/พื้นที่กลุ่ม และอุปกรณ์ที่พร้อมใช้งานตรงตามเงื่อนไขได้อย่างถูกต้อง

### AC-02 — การจองพื้นที่พร้อมอุปกรณ์ในขั้นตอนเดียว

- **Given** นักศึกษาเลือกห้องหรือพื้นที่กลุ่มที่ต้องการและยังว่างอยู่
- **When** ระบุจำนวนผู้เข้าใช้ เลือกอุปกรณ์การเรียนเสริมที่ต้องการยืม และกดยืนยันการจอง
- **Then** ระบบบันทึกข้อมูลการจอง ออกรหัสการจอง/QR Code สำหรับ Check-in และแสดงข้อความยืนยันสำเร็จ

### AC-03 — การยกเลิกหรือเปลี่ยนแปลงการจอง

- **Given** นักศึกษามีรายการจองพื้นที่/อุปกรณ์ที่ยังไม่ถึงกำหนดเวลาเข้าใช้งาน
- **When** กดยกเลิกการจอง หรือขอเปลี่ยนแปลงช่วงเวลาจองล่วงหน้าตามระยะเวลาที่กำหนด
- **Then** ระบบยกเลิกหรืออัปเดตรายการเดิม คืนสถานะห้อง/อุปกรณ์ให้ว่างสำหรับผู้อื่น และบันทึกประวัติการทำรายการ

### AC-04 — การยืนยันเข้าใช้งาน (Check-in)

- **Given** นักศึกษาเดินทางมาถึงพื้นที่จองภายในระยะเวลาที่กำหนด
- **When** สแกน QR Code ที่จุดบริการหรือหน้าห้องเพื่อยืนยันเข้าใช้งาน
- **Then** ระบบเปลี่ยนสถานะการจองเป็น "กำลังใช้งาน (In-Use)" หากเลยเวลาที่กำหนดโดยไม่ Check-in ระบบจะตัดสิทธิ์และเปลี่ยนสถานะเป็น "No-Show" อัตโนมัติ

### AC-05 — การตรวจรับ-คืนอุปกรณ์และบันทึกสภาพอุปกรณ์

- **Given** เจ้าหน้าที่ห้องเปิดหน้ารายการยืม-คืนอุปกรณ์การเรียน
- **When** เจ้าหน้าที่ห้องทำการเบิกจ่ายหรือรับคืนอุปกรณ์ พร้อมบันทึกสภาพอุปกรณ์ (ปกติ/ชำรุด)
- **Then** ระบบอัปเดตสถานะอุปกรณ์ในคลัง บันทึกประวัติการยืม-คืน และลงบันทึกใน Audit Log

### AC-06 — การอนุมัติคำขอใช้งานพื้นที่/อุปกรณ์พิเศษ

- **Given** มีรายการขอจองพื้นที่พิเศษหรือขอสงวนห้องส่งเข้ามา (จากนักศึกษา หรือ อาจารย์ / ผู้ดูแลห้อง)
- **When** เจ้าหน้าที่ห้องตรวจสอบรายละเอียดและทำการ "อนุมัติ" หรือ "ปฏิเสธ" คำขอ
- **Then** ระบบอัปเดตสถานะการอนุมัติและแจ้งเตือนผลไปยังผู้ส่งคำขอทันที

### AC-07 — การกำหนดเงื่อนไขและกฎการจอง

- **Given** ผู้ดูแลระบบ (System Admin) เข้าสู่หน้าตั้งค่าเงื่อนไขการใช้งาน
- **When** กำหนดระยะเวลาการจองสูงสุด จำนวนสมาชิกขั้นต่ำต่อห้อง หรือจำนวนครั้งที่อนุญาตให้จองต่อสัปดาห์
- **Then** ระบบบันทึกเงื่อนไขใหม่และใช้นำไปบังคับใช้กับการทำรายการจองทันที

### AC-08 — การสร้างรายงานสรุปสถิติการใช้งาน

- **Given** อาจารย์ / ผู้ดูแลห้อง หรือ ผู้ดูแลระบบ (System Admin) เข้าสู่หน้าเรียกดูรายงาน
- **When** เลือกช่วงเวลาและประเภทข้อมูลสถิติที่ต้องการวิเคราะห์ (เช่น อัตราการเข้าใช้ห้อง, อุปกรณ์ที่ถูกยืมมากที่สุด)
- **Then** ระบบประมวลผลและแสดงรายงานสรุปสถิติการใช้งานในรูปแบบกราฟและตารางได้อย่างถูกต้อง

### AC-09 — การตรวจสอบประวัติการใช้งานย้อนหลัง (Audit Log)

- **Given** ผู้ดูแลระบบ (System Admin) เข้าสู่หน้าตรวจสอบ Audit Log
- **When** ค้นหาประวัติการจอง การเข้าใช้งาน การยืม-คืน หรือการยกเลิกตามรหัสการจองหรือชื่อผู้ใช้
- **Then** ระบบแสดงรายละเอียดวันเวลา ผู้ทำรายการ และการเปลี่ยนแปลงสถานะ โดยไม่มีสิทธิ์ให้แก้ไขหรือลบประวัติ

### AC-10 — การควบคุมสิทธิ์การเข้าถึงตามบทบาท (RBAC)

- **Given** ผู้ใช้งานเข้าสู่ระบบด้วยบทบาทเฉพาะ (นักศึกษา, เจ้าหน้าที่ห้อง, อาจารย์ / ผู้ดูแลห้อง, ผู้ดูแลระบบ (System Admin))
- **When** เรียกใช้งานเมนูและฟังก์ชันต่างๆ ในระบบ
- **Then** ระบบอนุญาตให้เข้าถึงเฉพาะฟังก์ชันและข้อมูลที่ได้รับสิทธิ์ตามบทบาทนั้นๆ เท่านั้น

| Related Requirements        | FR-03, FR-04                                                                                                                                                                                                                                                                                                                                                 |
| Business Rules              | BR-02: ปลดล็อก/ตัดสิทธิ์อัตโนมัติเมื่อสายเกิน 15 นาที และต้องยกเลิกล่วงหน้าอย่างน้อย 30 นาที                                                                                                                                                                                                                                                                 |

## 7. Negotiation / Trade-off Notes

บันทึกสิ่งที่ไม่ได้เลือกหรือเลื่อนออกจาก scope พร้อมเหตุผล

- **ระบบปลดล็อกประตูห้องจองอัตโนมัติด้วย Smart Door Lock (IoT Integration):**
  - **ตัดสินใจ:** ตัดออกจาก Scope เฟสแรก ใช้การ Check-in ผ่านระบบ QR Code บน Web Application แล้วให้เจ้าหน้าที่ปลดล็อกหรือรับกุญแจ/คีย์การ์ดแทน
  - **เหตุผล:** ลดต้นทุนด้านอุปกรณ์ Hardware และความยุ่งยากในการเชื่อมต่อระบบเครือข่ายของอาคาร

- **ระบบปรับเงินอัตโนมัติกรณีคืนอุปกรณ์สายหรือทำอุปกรณ์ชำรุด (Auto-Fine Payment Gateway):**
  - **ตัดสินใจ:** ปรับเปลี่ยนเป็นการบันทึกแต้มความประพฤติ (Penalty Points) และระงับสิทธิ์การจองชั่วคราว (Block Account) หากทำผิดกฎ
  - **เหตุผล:** ลดความซับซ้อนในการเชื่อมต่อ Payment Gateway และข้อกำหนดด้านกฎหมายการเงินของสถาบัน

- **ระบบแนะนำห้องจองอัตโนมัติด้วย AI (AI-based Recommendation):**
  - **ตัดสินใจ:** เลื่อนไปพัฒนาในระยะถัดไป (Future Scope)
  - **เหตุผล:** เน้นการพัฒนาฟังก์ชันการค้นหาและกรองข้อมูลตามเงื่อนไข (Filtering System) ให้เสถียรก่อน ลด User Story ลง
