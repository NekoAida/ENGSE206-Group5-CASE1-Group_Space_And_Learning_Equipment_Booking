## 1. รายการคำถามค้างสำหรับสอบถามอาจารย์ (Open Questions for Week 06 Opening)

| OQ ID | หมวดหมู่ / Requirement | คำถามที่ต้องการความชัดเจน | บริบทและผลกระทบต่อระบบ | ผู้เกี่ยวข้องหลัก |
|---|---|---|---|---|
| **OQ-01** | Business Rule / Exception (BR-02) | ควรมีกลไกยื่นคำขออนุมัติกรณีพิเศษ (Special Exception Request) เพื่อให้จองห้องเกินโควตา 3 ชั่วโมง/วัน สำหรับนักศึกษาที่ทำโครงงานปริญญานิพนธ์หรือไม่? | หากต้องมี ระบบจะต้องเพิ่ม Workflow คำขอพิเศษพร้อมการอนุมัติจากอาจารย์ที่ปรึกษา | ผู้จัดการพื้นที่ / อาจารย์ประจำวิชา |
| **OQ-02** | Concurrency & Policy (BR-01) | ในกรณีที่อุปกรณ์ชิ้นสุดท้ายมีผู้ส่งคำขอจองเข้ามาพร้อมกันในเสี้ยววินาที ระบบควรใช้เกณฑ์ First-Come First-Served โดยสมบูรณ์ หรือมีลำดับความสำคัญตามระดับชั้นปี/ความจำเป็นของกิจกรรม? | มีผลต่อการออกแบบ Database Locking และ Concurrency Handling Logic | เจ้าหน้าที่ดูแลอุปกรณ์ / ทีมพัฒนา |
| **OQ-03** | User Penalty & Policy (FR-03) | เกณฑ์การตัดสิทธิ์การใช้งาน 7 วันเมื่อ No-show ครบ 3 ครั้ง ควรมีระบบยื่นคำร้องอุทธรณ์ (Appeal Form) บนหน้าเว็บกรณีมีเหตุสุดวิสัยหรือไม่? | หากมี จะต้องเพิ่ม Use Case การจัดการอุทธรณ์ของเจ้าหน้าที่/ผู้บริหาร | ผู้จัดการพื้นที่ / งานกิจการนักศึกษา |
| **OQ-04** | Communication Interface (FR-04) | นอกเหนือจาก Web Notification และ Email สถาบัน มีความจำเป็นต้องเตรียม Webhook หรือ Messaging API รองรับระบบแจ้งเตือนภายนอกในอนาคตหรือไม่? | ช่วยวางขอบเขต Architecture ของ Notification Service ไม่ให้เกินขอบเขตโครงงาน | เจ้าหน้าที่ IT สถาบัน |
| **OQ-05** | Dashboard Metrics (FR-06) | สถิติและตัวชี้วัดบน Dashboard ที่ผู้บริหารต้องการเน้นหนัก ควรเป็น Utilization Rate รายช่วงเวลา หรือ รายงานสถิติอุปกรณ์ชำรุด/สูญหาย? | ใช้กำหนด Data Aggregation Queries และการเลือกประเภทแผนภูมิแสดงผล | ผู้บริหารสถานศึกษา / ผู้จัดการพื้นที่ |
| **OQ-06** | Asset Management Workflow (FR-05) | ในขั้นตอนการรับคืนอุปกรณ์ หากเจ้าหน้าที่ระบุว่าอุปกรณ์ "ชำรุด" หรือ "อุปกรณ์ไม่ครบ" ระบบควรเปลี่ยนสถานะเป็น Out-of-Service อัตโนมัติและส่งเรื่องต่อยังฝ่ายใด? | ใช้กำหนด Lifecycle State Transition ของ Entity อุปกรณ์การเรียนรู้ | เจ้าหน้าที่ดูแลห้อง / ฝ่ายพัสดุ |
